# Ограничения пилота

Честный список — что упрощено, что заменено, что не сделано, и почему.
Ничего из этого не скрыто из результатов; ниже — расшифровка каждого пункта.

## Отклонения от исходного протокола (config/protocol.yaml)

1. **Декои Теста A и baseline Теста B: ChEMBL вместо ZINC.**
   Протокол изначально предполагал property-matched декои из ZINC (option A).
   Из-за ограничений по времени на пилоте декои/baseline взяты из общего
   пула ChEMBL (~2М соединений) вместо ZINC: тот же матчинг по свойствам
   (MW, ALogP, HBD, HBA, RTB, допуски в `config/protocol.yaml`) + фильтр
   Tanimoto ECFP4 < 0.35 к любой активной молекуле, но источник кандидатов
   другой. Научная логика теста (различает ли докинг-скор активные от
   структурно других, но похожих по свойствам молекул) не меняется.
   См. `src/01_data_curation/curate_test_a.py` и
   `src/06_generation/test_b_generation.py`.

2. **Watchdog / устойчивость к перезагрузке машины: не реализован через
   Windows Task Scheduler.** Вместо этого — один долгоживущий процесс
   (`src/common/orchestrate.py`) с try/except на каждом этапе: падение
   одного этапа не останавливает весь пайплайн, следующий этап всё равно
   запускается. Если сама машина перезагрузится или процесс будет убит
   ОС/пользователем -- пайплайн НЕ поднимется автоматически, его нужно
   перезапустить вручную (`python src/common/orchestrate.py`,
   идемпотентен: уже посчитанные этапы пропускаются).

3. **Приватный репозиторий не создан.** Разделение public/private
   реализовано частично: `src/common/anonymize.py` пишет обезличенные
   (`*_public.csv`, ligand_id вместо SMILES) копии рядом с полными
   данными; полные данные (с SMILES) в `.gitignore`, НЕ коммитятся вообще
   -- ни в публичный, ни в несуществующий приватный репозиторий. Значит:
   ligand_id -> SMILES маппинг сейчас нигде не запушен, только локально на
   машине. Если нужен второй (приватный) репозиторий -- решение и
   создание за пользователем.

4. **Windows power-settings hardening (сон/гибернация/автообновления) не
   выполнен.** Не было прав/времени проверить и настроить безопасно
   автоматически; пользователь подтвердил, что машина гарантированно не
   выключается 48 часов, так что это снижает риск, но не устраняет его
   полностью (гибернация по таймауту, Windows Update reboot и т.п. не
   исключены).

5. **Task 0 (redock)** реализован с полной проверкой (RMSD через
   `rdMolAlign.GetBestRMS`, учитывает симметрию/эквивалентные атомы) --
   единственный этап, доведённый без упрощений.

## Упрощения научной части

- **Фильтр стерических клэшей сгенерированных молекул с белком (Тест B)
  не реализован.** Проверяется только: RDKit-валидность/санитайзинг
  (через `--sanitize` в DiffSBDD) и центр масс молекулы внутри
  докинг-бокса. Полноценная проверка клэшей (минимальное расстояние до
  любого атома рецептора) — не сделана; часть невозможных геометрий,
  вероятно, всё же проходит в докинг, но не отсеивается заранее.

- **Подвыборка активных для Теста A: 250 из 2568.** Фиксированный seed=42,
  случайная подвыборка (не стратифицированная по химическому пространству).
  Сделано ради времени докинга; при 250 активных x ~30 декоев тест всё
  равно превышает минимум (50) на порядок.

- **N_PER_SEED=60 для Теста B** (не более крупное число) -- баланс между
  статистической мощностью и временем генерации+докинга на пилоте.

## Что НЕ было проверено вручную

- Корректность самой формулы BEDROC не переизобреталась -- используется
  `rdkit.ML.Scoring.Scoring.CalcBEDROC` (готовая, протестированная
  реализация), а не написанная с нуля.
- Случайный базовый уровень BEDROC считается ЭМПИРИЧЕСКИ (много
  перемешиваний меток), а не по замкнутой формуле Truchon & Bayly --
  сознательный выбор ради воспроизводимости и переиспользования кода с
  Тестом N, см. docstring `src/05_metrics/bedroc_calibration.py`.

## Общее

Это пилотный прогон на одной рабочей станции, не финальное исследование.
Число активных/декоев, число сидов генерации, exhaustiveness Vina -- всё
выбрано с учётом времени, а не научного идеала. `docs/scale-up.md`
описывает, что меняется при переносе на кластер.
